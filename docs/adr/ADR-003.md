# ADR-003: JWT Bearer Tokens over Session-Based Auth

- **Status**: Accepted
- **Date**: 2024-06-01
- **Deciders**: Technical Lead, Architects

## Context

The gym system requires mobile app support (React Native planned), making cookie-based session auth problematic due to cross-domain cookie sharing requirements. The application needs to scale horizontally across multiple instances without a shared session store. Stateless authentication eliminates the need for Redis/Memcached for session storage and reduces database lookups on every request.

## Decision

Use JWT access tokens (15-minute expiry) with refresh tokens (7-day expiry stored in httpOnly cookies). Implement refresh token rotation — each refresh issues a new refresh token and invalidates the previous one.

## Consequences

- (+) Fully stateless — access tokens can be verified without database lookups.
- (+) Works seamlessly across domains and mobile platforms via Authorization header.
- (+) Horizontal scaling is trivial — no shared session store needed.
- (-) Token revocation is inherently difficult — mitigated by short access token expiry and refresh token rotation.
- (-) JWT size overhead (typically 500-1000 bytes per token) increases request size.
- (-) Refresh token rotation adds complexity to the auth flow and requires a token family database.

## Compliance

Access tokens must use RS256 signing with a rotating key pair. Refresh tokens must be stored as httpOnly, Secure, SameSite=Strict cookies. Token blacklisting must be implemented on the refresh endpoint for rotation invalidation. All authentication logic must reside in a dedicated auth service module.
