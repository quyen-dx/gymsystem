# ADR-005: VNPAY + Stripe Dual Payment System

- **Status**: Accepted
- **Date**: 2024-06-01
- **Deciders**: Technical Lead, Architects

## Context

The gym system must serve both Vietnamese and international customers. Vietnamese users require domestic payment methods including VNPAY (QR code, ATM/bank transfer) and direct bank transfers. International users need credit/debit card support via Stripe. Each payment method has different regulatory requirements, webhook formats, and refund processes. A wallet system is needed to manage internal balances for memberships, PT sessions, and product purchases.

## Decision

Integrate VNPAY for domestic Vietnamese payments and Stripe for international card payments. Implement an internal wallet system that supports deposits via both providers and deducts for services consumed. Use a unified payment transaction model with provider-specific metadata.

## Consequences

- (+) Full payment coverage for both Vietnamese and international customers.
- (+) Wallet system enables flexible pricing (packages, credits, subscriptions).
- (+) Each provider handles its own compliance (PCI-DSS for Stripe, SBV regulations for VNPAY).
- (-) Two separate integrations with different APIs, webhook formats, and SDKs must be maintained.
- (-) Different refund flows — Stripe supports instant refunds, VNPAY refunds require manual processing.
- (-) Reconciliation is more complex with multiple providers and the internal wallet ledger.

## Compliance

All payment transactions must be recorded in a transactions collection with provider, status, and amount. Webhook endpoints must verify signatures for both providers. Wallet balance changes must use MongoDB transactions. Payment provider credentials must be stored in environment variables, never in code.
