# ADR-006: TanStack Query (React Query) over Redux

- **Status**: Accepted
- **Date**: 2024-06-01
- **Deciders**: Technical Lead, Architects

## Context

The majority of the gym frontend's state is server-derived — memberships, bookings, check-ins, user profiles, and AI chat responses. Complex client-only state is minimal (form inputs, UI toggles). Redux would introduce significant boilerplate (actions, reducers, selectors, middleware) for state that is primarily fetched and cached from the API. The team prefers a simpler solution with less conceptual overhead.

## Decision

Use TanStack Query (React Query) v5 for all server state management (fetching, caching, synchronization). Use React Context for minimal global client state (current user, theme, locale settings). Do not use Redux.

## Consequences

- (+) Automatic caching with configurable stale times reduces redundant API calls.
- (+) Request deduplication prevents multiple simultaneous requests for the same data.
- (+) Background refetching keeps data fresh without manual polling logic.
- (+) Optimistic updates enable instant UI feedback for mutations (bookings, check-ins).
- (-) Team must learn TanStack Query patterns (queries, mutations, query keys, cache invalidation).
- (-) TanStack Query is less suitable for complex client state like multi-step forms with cross-step validation — these should use local state or a lightweight form library.

## Compliance

All API calls must use TanStack Query hooks — raw fetch/axios calls in components are not permitted. Query keys must follow a consistent naming convention (resource name + parameters). Mutations must invalidate relevant queries on success.
