# ADR-002: Express 5 over NestJS/Fastify

- **Status**: Accepted
- **Date**: 2024-06-01
- **Deciders**: Technical Lead, Architects

## Context

The project was initiated before NestJS was evaluated as an alternative. The team has extensive experience with Express and is productive with its middleware model. The application requires a mature ecosystem for authentication middleware (Passport), file upload handling (Multer), CORS configuration, and rate limiting. NestJS would require a steep learning curve and significant refactoring of existing code. Fastify offers better performance but has a smaller middleware ecosystem and fewer community resources.

## Decision

Continue development with Express 5 but pin production deployments to Express 4 LTS until Express 5 reaches stable LTS status. Use express-async-errors for async error handling.

## Consequences

- (+) Largest middleware ecosystem in Node.js — any needed middleware is readily available.
- (+) Simple, intuitive middleware model that the entire team understands.
- (+) Easy debugging and profiling with standard Node.js tooling.
- (-) No built-in dependency injection — services must be manually wired or use lightweight DI containers.
- (-) No opinionated project structure — teams must enforce conventions through code review and linting.
- (-) Express 5 is not yet LTS — production use carries risk of breaking changes in minor versions.

## Compliance

All middleware must be registered in a central app configuration file. Error-handling middleware must be the last middleware in the chain. Controllers must be separated from route definitions.
