# ADR-008: Monorepo (Single Repository) over Separate Repos

- **Status**: Accepted
- **Date**: 2024-06-01
- **Deciders**: Technical Lead, Architects

## Context

The gym system consists of a React frontend and an Express backend that share domain types, utility functions, and business logic. A single team maintains both codebases. Separate repositories would require coordination across repos for shared type changes, synchronized deployments, and cross-stack feature development. Version mismatches between frontend and backend types have already caused production bugs.

## Decision

Use a single monorepo with two top-level directories: /gym-frontend and /gym-backend. Share domain types by duplicating definitions in /gym-frontend/src/types and /gym-backend/models, kept in sync via a shared reference document and code review process. Use npm workspaces for dependency management.

## Consequences

- (+) Simplified development workflow — one clone, one branch, one PR for cross-stack changes.
- (+) Atomic commits ensure frontend and backend changes are always synchronized.
- (+) Easier onboarding — new developers only need to clone one repository.
- (+) Shared CI/CD pipeline can run frontend and backend tests together.
- (-) Larger clone size impacts initial setup time.
- (-) CI/CD must handle both frontend and backend — pipeline configuration is more complex.
- (-) Risk of coupling between frontend and backend — teams must be disciplined about separation of concerns in PR reviews.
- (-) Shared dependencies can cause version conflicts between frontend and backend (e.g., different TypeScript versions).

## Compliance

The frontend must never import directly from backend source files. Shared types must be duplicated and kept in sync. CI pipeline must run tests for both frontend and backend. PRs affecting both stacks must pass both test suites.
